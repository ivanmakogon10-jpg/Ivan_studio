# Ivan Studio — исходники сайта

Сайт собран на чистых HTML / CSS / JavaScript. Без сборщика, без зависимостей,
без внешних библиотек — открывается и работает как есть.

## Структура

```
src/         рабочие исходники
  head.html    meta-теги, шрифты, favicon
  body.html    разметка страницы
  styles.css   визуальная система: токены, светлая/тёмная тема, адаптив
  data.js      ВЕСЬ редактируемый контент
  particles.js поле частиц первого экрана (независимый модуль)
  app.js       интерактив

  assets/      изображения проектов

reference/   исходный React-компонент и заметки по нему (в сборку не входит)

standalone/  готовый сайт — залейте эту папку на хостинг
dist/        сборка для публикации внутри Claude
build.py     пересборка: python3 build.py
```

Правится только `src/`. После правок запустите `python3 build.py` —
он соберёт `standalone/` и `dist/`.

## Как добавить проект

В `src/data.js`, массив `PROJECTS`:

```js
{
  id: 'my-project',
  number: '04',
  title: 'Название',
  summary: 'Короткое описание.',
  categories: ['Web Design', 'Development'],
  year: '2026',
  sector: 'Business',              // английская строка категории: Sport / Restaurant / …
  status: 'released',
  cover: 'flow',                    // генеративная обложка: arc | menu | flow
  media: {
    preview: 'img/my/preview.jpg',  // обложка в сетке; заменяет генеративную
    desktop: 'img/my/desktop.jpg',  // десктопный экран в кейсе
    mobile:  'img/my/mobile.jpg',   // мобильный экран в кейсе
    gallery: [{ src: 'img/my/1.jpg', alt: 'Каталог' }]
  },
  span: { col: 'span 4', ratio: '4 / 3' },
  case: {
    role: ['Дизайн', 'Разработка'],
    task: 'Что требовалось сделать.',
    solution: 'Как решено.',
    stack: ['HTML', 'CSS', 'JS'],
    process: ['Исследование', 'Прототип', 'Дизайн', 'Вёрстка']
  }
}
```

Пустые поля `case` показываются как «Раздел в подготовке» — заполните,
и они появятся в кейсе. Пустой `media.preview` — рисуется генеративная обложка
с подписью «Превью — место под изображение».

Раскладка плитки: `span 12` — во всю ширину, `span 4` — треть, `span 6` — половина.
Пропорция `ratio` любая: `'16 / 7'`, `'4 / 3'`, `'3 / 4'`.

## Концептуальные проекты

Массив `CONCEPTS`. Пока `status: 'soon'` — проект стоит в панели
«Концептуальные проекты» с пометкой «Скоро» и не открывается.
Заполните `media` и `case`, поставьте `status: 'released'` — карточка
сама встанет в сетку работ, а нумерация и счётчик «01 — 06» обновятся.

## Контакты

Объект `CONTACTS` в начале `data.js`. Ссылки, `mailto:` и `tel:`

## Приём заявок

Обработчик уже в репозитории: `api/brief.js` — serverless-функция,
пересылает заявку с формы в Telegram. `data.js` указывает на неё через
`BRIEF_ENDPOINT = '/api/brief'`. Пока сайт не задеплоен туда, где эта
функция реально выполняется (Vercel), форма честно предупреждает:
«Форма пока находится в режиме предварительной настройки» — и
предлагает написать напрямую. Ответы при этом сохраняются в
localStorage браузера посетителя (ключ `ivan-brief-draft`), но до вас
не доходят.

### Как подключить (Vercel + Telegram-бот)

1. **Создайте Telegram-бота.** В Telegram откройте @BotFather →
   `/newbot` → задайте имя. BotFather выдаст токен вида
   `123456789:AA...` — это `TG_TOKEN`.
2. **Узнайте свой chat_id.** Напишите новому боту любое сообщение
   (например «привет»), затем откройте в браузере
   `https://api.telegram.org/bot<TG_TOKEN>/getUpdates` (вместо
   `<TG_TOKEN>` — токен из шага 1) и найдите в ответе
   `"chat":{"id":...}` — это число и есть `TG_CHAT`.
3. **Задеплойте репозиторий на Vercel.** vercel.com → войти через
   GitHub → Add New Project → выбрать репозиторий `Ivan_studio`.
   В настройках сборки: Framework Preset — Other, Build Command —
   `python3 build.py`, Output Directory — `standalone`.
4. **Добавьте переменные окружения.** В Project Settings →
   Environment Variables добавить `TG_TOKEN` и `TG_CHAT` со
   значениями из шагов 1–2. Deploy.
5. После деплоя форма на сайте будет реально доставлять заявки в
   Telegram; «Заявка отправлена» покажется только при успешном ответе
   сервера.

### Безопасность

**Токен Telegram-бота и любые другие ключи нельзя класть в `data.js`,
`app.js` или HTML.** Этот код отдаётся браузеру как есть, и любой
посетитель увидит ключ, сможет читать чужие сообщения бота и писать
от его имени. Секреты живут только на серверной стороне — в
переменных окружения Vercel, `api/brief.js` их оттуда и читает.

## Цены и расчёт

`SERVICES` — блок «Что можно сделать» (`label` — английская метка над названием),
`SERVICES_NOTE` — сноска под списком.
`CALC` — экономика расчёта: `base` (стартовая сумма типа), `mult` (множители),
`add` (надбавки), `spread` (насколько верхняя граница выше нижней).
`QUIZ_STEPS` — порядок вопросов в блоке «Ориентировочная стоимость»; каждый шаг
ссылается на группу в `CALC` через `key`.
Нижняя граница никогда не опускается ниже цены «от» из `CALC.type` —
расчёт не может назвать сумму меньше опубликованного прайса.
Кнопка «Получить расчёт» переносит ответы в заявку и ведёт сразу к контактам.

## Первый экран

Титульный экран студии: только типографика по центру и поле частиц
вокруг неё. Устройств здесь нет — они появляются ниже, в секции
живого показа, чтобы заголовок ни с чем не конкурировал.

Содержимое задаётся объектом `HERO` в `data.js`: метка, заголовок
построчно (`soft: true` — строка светлее и тоньше), подпись, две
кнопки и `heroProject` для счётчика внизу.

**Поле частиц** — `particles.js`, настраивается объектом `PARTICLES`:

| ключ | что делает |
| --- | --- |
| `density`, `speed` | плотность и скорость дрейфа |
| `dotSize`, `bigShare` | базовый радиус точки и доля крупных «звёзд» |
| `glow`, `twinkle` | ореол вокруг крупных точек и сила редкого мерцания |
| `dotAlpha`, `linkAlpha` | прозрачность точек и связей между ними |
| `linkDistance` | до какого расстояния соединять соседей |
| `pointerRadius`, `pointerPush` | радиус реакции на курсор и на сколько px точки от него отходят |
| `opacity` | общая прозрачность слоя |

Точки расходятся от курсора: чем ближе точка, тем сильнее смещение
(до `pointerPush` пикселей), дальние почти не двигаются. Сама позиция
точки при этом не меняется — смещение живёт только в кадре, поэтому
поле спокойно возвращается на место. Цвет берётся из токенов
`--field-dot` и `--field-link`, заданных на `.hero` для каждой темы.
На тач-устройствах реакция на курсор не подключается, при
`prefers-reduced-motion` поле замирает.

## Живой показ проектов

Секция между первым экраном и списком работ. Сначала из глубины
выходят MacBook и iPhone, затем камера входит в экран ноутбука,
корпус уезжает за края, и сайт проекта открывается во весь экран —
настоящий, а не скриншот. Стрелками переключаются три проекта.

**Как устроено.** Сцена собирается в своей системе координат —
«пластине» 1560×980. В ней лежат ноутбук, экран с живым сайтом и
телефон, каждый на своём месте. Пластина получает одну проективную
матрицу (`matrix3d`), которая тянет её четыре угла от стартового
положения к тому, при котором экран ноутбука точно совпадает с окном.
Корпус уезжает за край сам — он часть той же пластины.

Этапы по прогрессу прокрутки секции:

| прогресс | что происходит |
| --- | --- |
| 0.02–0.12 | проступает подпись секции |
| 0.12–0.32 | устройства выходят из глубины, подпись уходит |
| 0.32–1.00 | камера входит в экран ноутбука |
| 0.34–0.58 | телефон покидает композицию |
| 0.88–1.00 | появляется навигация проекта |

**Прокрутка ни от чего не зависит.** Прогресс считается только от
положения секции в документе; курсор на него не влияет и ничего не
блокирует. Пока идёт наезд, фреймы проектов не принимают события мыши
— колесо всегда достаётся странице, где бы ни стоял курсор, и наезд
не «залипает».

**В полноэкранном состоянии проект оживает.** Активный фрейм получает
`pointer-events: auto`: внутри работает всё, что есть в самом сайте —
меню, кнопки, формы, наведения, собственная прокрутка. Секция
проставляет себе `data-state`: `intro` → `devices` → `zoom` →
`project`, по нему и переключается интерактивность. Чтобы выйти, есть
Esc, кнопка рядом со стрелками и подсказка, которая коротко
появляется при входе. Стрелки и вся навигация лежат вне фрейма,
поэтому работают всегда. На тач-устройствах фрейм остаётся пассивным:
иначе он перехватывал бы вертикальный свайп. Сайт целиком открывается
кнопкой «Открыть проект» в новой вкладке.

**Устройства** — два отдельных PNG/WebP с прозрачным фоном:

| файл | что это |
| --- | --- |
| `assets/hero/mac.webp` | MacBook с вырезанным насквозь экраном (+ `.png`) |
| `assets/hero/iphone.webp` | iPhone с вырезанным экраном (+ `.png`) |
| `assets/projects/mobile/*.jpg` | мобильные снимки проектов для экрана телефона |

Экраны вырезаны насквозь, поэтому живой сайт лежит ПОД картинкой:
рамка и корпус остаются спереди без второго корпуса поверх.
`overflow: hidden` стоит только на самой сцене (граница окна) и на
экранах устройств — корпуса нигде не подрезаются.

**Настройка** — объект `SHOWCASE` в `data.js`:

- `height` — высота секции в vh: больше значение, медленнее наезд;
- `plate` — размер системы координат сцены;
- `mac` / `phone` — файл, положение, размер и четыре угла экрана
  в координатах пластины. Меняете картинку устройства —
  пересчитайте `screen`, иначе сайт не ляжет в экран;
- `frame`, `phoneFrame` — логический размер страницы внутри экранов:
  по нему проект решает, показывать десктопную вёрстку или мобильную;
- `note` / `noteFlat` — подпись для полной и упрощённой версии.

**Проекты** берутся из `PROJECTS`: показывается каждый, у кого есть
поле `live`:

```js
live: {
  path: 'projects/kempo/index.html', label: 'KEMPO', meta: 'SPORT / WEB DESIGN',
  mobile: 'assets/projects/mobile/kempo-mobile.jpg'
}
```

Путь относительный — это важно для GitHub Pages: сайт работает и в
корне домена, и в подпапке репозитория. Первый проект грузится сразу,
остальные — когда наезд перевалил за треть или через пару секунд
после загрузки, чтобы между проектами не было пустого экрана.

**Навигация.** В полноэкранном состоянии шапка студии уезжает наверх,
и остаётся минимум: крупные круглые стрелки по бокам (62px, тап-цель
больше 48px), внизу слева номер, название и категория проекта, внизу
справа кнопка «Открыть проект ↗» и выход. Стрелки работают мышью и
клавишами ←/→, выход — Esc или кнопкой.

**Узкие экраны и `prefers-reduced-motion`.** Наезда нет: секция
превращается в обычный просмотрщик — заголовок, окно с живым сайтом,
кнопка «Открыть проект» во всю ширину, счётчик и стрелки.

## Избранные проекты

Каждый проект — строка во всю ширину: слева номер, название, категории и
«Открыть кейс», справа крупное превью. При наведении название и ссылка
сдвигаются, превью наезжает, поверх проступает `View case`. Клик открывает
кейс. Номера и категории берутся из `PROJECTS`; строка `sector` даёт
английскую часть подписи (`Sport / Web Design / Development`).

## Кейс проекта

В `case` каждого проекта есть два необязательных поля:

```js
case: {
  role: ['Дизайн', 'Разработка'],
  task: '', solution: '', stack: [], process: [],
  deliverables: [],   // чек-лист «Реализовано» — ваши пункты
  url: ''             // ссылка на живой сайт → кнопка «Перейти на сайт»
}
```

Пустые значения не выводятся вовсе, незаполненные `task` / `solution` /
`stack` / `process` показываются как «Раздел в подготовке».

## Индикатор прокрутки

Тонкая полоса сверху. В браузерах с поддержкой `animation-timeline: scroll()`
ведётся средствами CSS без единого обработчика; где поддержки нет —
подключается запасной путь на JS.

## Поле частиц

Фон первого экрана — `src/particles.js`, независимый модуль без зависимостей.
Точки медленно дрейфуют, ближние соединяются волосяными линиями, курсор
притягивает соседей акцентным цветом. Цвета берутся из токенов
`--ink-3`, `--line-2`, `--acc`, поэтому поле переключается вместе с темой.

Настройки — объект `PARTICLES` в `data.js`:

```js
const PARTICLES = {
  enabled: true,        // false — выключить целиком, канвас удалится из DOM
  density: 0.9,         // множитель количества точек
  speed: 0.85,          // скорость дрейфа
  linkDistance: 118,    // px, до какого расстояния соединять соседей
  pointerRadius: 170,   // px, радиус реакции на курсор; 0 — без реакции
  opacity: 0.85         // общая прозрачность слоя
};
```

Слева поле гасится CSS-маской (`.hero__field`), чтобы крупный заголовок
оставался чистым. На мобильных маска разворачивается сверху вниз.

Модуль сам ставит кадры на паузу, когда первый экран уходит из вида или
вкладка уходит в фон, а при `prefers-reduced-motion: reduce` рисует один
статичный кадр вместо анимации.

Перенести поле в другую секцию: положите `<canvas class="hero__field">`
в нужный блок (блоку нужен `position: relative`) и вызовите
`ParticleField.mount(canvas, options)` — модуль ничего не знает о сайте.

## Типографика

Вся вёрстка живёт на девяти ступенях, объявленных в `:root` файла `styles.css`:
`--t-display`, `--t-h1`, `--t-h2`, `--t-h3`, `--t-h4`, `--t-lead`, `--t-body`,
`--t-small`, `--t-lab`. Одиночных `clamp()` в компонентах нет — единственное
осознанное исключение `.sheet__link` (мобильное меню, 8.5vw).
Если добавляете элемент, берите размер из шкалы, а не пишите свой.

Шрифты: Onest (Google Fonts, вариативный, кириллица) и JetBrains Mono для
номеров, цен и меток.

## Анимация входа

Первый экран собирается сдвигом: метка, строки заголовка, правая колонка,
метастрока и плита проекта по очереди встают на место. Реализовано чистым
CSS (`@keyframes heroSettle` / `heroLine`), без JS и без класса-переключателя.

Важное ограничение, которое здесь соблюдено: **текст нигде не прячется**.
Используется `animation-fill-mode: forwards`, поэтому до старта анимации и
в любом рендерере, который её не проигрывает (превью, скриншот, режим
экономии), элементы стоят в естественном видимом положении. Первый кадр
страницы всегда читаемый.
